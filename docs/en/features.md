# Discover what you can do with Galaris

Galaris brings an AI agent team and a shared workspace together. This tour explains uses and how
they combine, from everyday conversation to collaborative work lasting several weeks. Procedures
belong in the guides; the exhaustive inventory, also used to prepare the product website, remains
in the separate [functional catalogue](reference/functional-catalogue.md).

## Start with a conversation, expand when needed

After installation and entering an OpenRouter token, the Galaris agent and its models are already
configured. Start chatting, then progressively add agents, tools and integrations through the
graphical interface. Asking a first question requires no team design or workflow construction.

The application works on desktop and mobile, with English/French interfaces, light/dark themes
and PWA installation. Navigation, search, notifications and monitoring keep routine work accessible.
For installation/update commands, follow the [installation guide](admin/installation.md).

## Talk to an agent that can keep working

A conversation can remain a simple exchange or initiate research, analysis or production. Attach
files, dictate, send voice notes and find the resulting documents, Tasks and Processes. Long work
can continue while the conversation resumes.

Two complementary loops support this: the conversational loop maintains the exchange and context;
the work loop assigns Tasks to execution harnesses. An existing business treatment can also run
through a Process engine such as n8n.

Text is not the only channel: compatible resources enable live voice calls. Configured Matrix,
Nextcloud Talk, Telegram, WhatsApp and OneBot integrations also connect external channels. Files,
history and voice capabilities vary by channel.

## Build a team with real delegation

Every agent has a durable identity, mission, personality, skills and tools. Specialists can join
teams of humans and agents, with access suited to their roles.

While preparing a study, an agent can ask a colleague for research or review. That contribution
becomes identifiable work: responsibilities, expected outcomes, dependencies, unanswered questions
and results are visible. A plan can divide a complex request into child Tasks and assemble their
conclusions.

Shared documents support this collaboration. Agents need not pass successive summaries of a
supposed deliverable that nobody can actually retrieve.

## Write with agents and reuse the knowledge

Reports, notes, analyses and drafts live in a shared document library. A human can open a document
beside chat, correct it and ask the agent to enrich the same content. Saves and versions make
contributions traceable, allow comparison and restore earlier content. Concurrent edits produce
explicit conflicts; this is not real-time keystroke merging.

Rich text includes tables, callouts, images, attachments and resource links. Dictation, speech
playback, print, PDF and HTML archives make work useful beyond chat. Each reader chooses personal
folders and icons without imposing that organisation on others.

Documents also form a **knowledge base**: authorised searches can retrieve their content, references
and attachments. Sharing with a human, agent or team makes joint work accessible without copying it
everywhere.

## Turn a document into a usable tool

A document can contain a form, calculator, chart or small application. The agent writes the page;
the human retains editable explanations and opens code through Source. A method and the calculator
that applies it can occupy the same documentary space.

Dataset documents store JSON separately. Several pages can share reference data, collect responses
or inspect common results—for example, an input page and a monitoring page used by one team.

Page rights, data rights and personal consent for the application are separate. Exports retain a
static view of the displayed result for sharing or archiving a state of the work.

## Recover context over time

Memory helps agents find facts, decisions and knowledge useful to the current request. Search
combines words, meaning and resource relationships while respecting rights and validity. Contacts
associate exchanges with people; Topics gather activity spread across conversations, Tasks and
documents.

Dream uses available time to classify and consolidate knowledge. It can extract durable information
from completed work, identify duplicates/conflicts and, when enabled, describe attachments lacking
text. Procedural learning can also derive methods from several evidence-supported experiences.

Users can inspect, correct, share, review history, explore the graph and explicitly forget memory.
Learning and optional analyses are not all enabled by default, and recall does not guarantee every
piece of information will surface in every exchange.

## Entrust an objective that lasts

A Task targets a result; a Goal organises successive work cycles around a continuing objective.
Assign recurring research or monitoring, define working windows, designate a human referrer and
inspect successive results. Follow-up and produced documents remain linked to the objective.

After each cycle, Galaris examines the outcome to continue or stop. The agent can ask its referrer
for a missing decision. Humans can pause, resume, finish or request an immediate cycle. Calendar
events and alarms can also trigger Tasks or Processes.

## Give agents practical means to act

Tools cover web search, interactive browsing, files and, for equipped agents, a Linux console.
Agents can consult sources, manipulate resources, work on a repository, start a long command and
check results in a browser. URIs identify the same files across tools.

Skills provide reusable methods; connected MCP servers extend capabilities. Conversely, Galaris
can expose an agent's authorised tools to external MCP clients. n8n Processes provide reusable
business workflows tracked from submission to outcome.

Email adds message search/reading, attachment processing and reply preparation. Where configured,
sending waits for a human to approve the exact content. Calendars add availability checks, free-slot
search and event management.

## Work with multimedia

A meeting recording can become verbatim text and synthesis, then minutes revised with the agent.
YouTube videos with public subtitles can feed the same work. Viewers cover PDF, images, audio,
video, Markdown, code and several 3D formats without forcing an external download for each inspection.

With compatible models, agents can analyse images, sound and video, create/edit illustrations and
start music, sound-effect or video generation. Long productions are tracked as Processes and their
files remain linked to the originating work. Each provider retains its own capabilities and limits.

## Choose models and harnesses for the work

Profiles group conversational, execution and specialised resources, allowing several providers or
local models to coexist. Harnesses run the agent: Galaris supplies its internal harness and
integrations such as Hermes, Claude Agent, Codex and DeepSeek Harness, each with its own capabilities.

Bounded choices—routing a Task, selecting a Topic or recognising already-covered knowledge—can use
a **Decision model**, such as JEV through OpenRouter. Drafting remains with a text model. Traces and
evaluation preserve this distinction without assuming specialised models are always better or cheaper.

Compatible development clients can also use profiles through stable identifiers, with calls tracked
inside Galaris.

## Understand outcomes and measure improvements

Activity views expose Tasks, steps, delegation, model/tool calls, waits, results and errors. They
support intervention in active work and recovery of history after reconnecting. Costs and usage
remain qualified by the information actually supplied; incidents have durable diagnostic dossiers.

The Lab turns observed difficulties into evaluation cases or prepares synthetic cases for review.
Compare models, prompts or settings, repeat trials, separate candidates from judges and confront
results with human review. Authorised agents can run campaigns and submit their own assessments,
separate from other evaluations.

This supports changes based on inspectable evidence. The Lab does not automatically change
production settings, and a benchmark does not prove every possible use.

## Keep control of your installation

Self-hosting brings accounts, roles, teams, connections and resource sharing under common
administration. Tasks/Processes retain state, and recovery uses available evidence to avoid blindly
repeating external effects. Unknown outcomes can require a human decision.

Effective capabilities depend on configured permissions, connections and models. A local model does
not automatically make other services local. The interface provides usage settings and activity
monitoring; backups, updates and operating checks belong to the administrator.
